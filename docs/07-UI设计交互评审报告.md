# 07 - UI 设计交互评审报告（报告一：视觉/体验层）

- 日期：2026-07-19
- 设计依据：`docs/03-架构设计.md`（场景与 UI 层）
- 基准：原版 Android Build 2900（9 Activity + 11 UI 组件类）vs 桌面版（9 Screen + UiRenderer）
- 方法：3 个只读分析代理并行 + 主线程逐条复核 P0/P1
- 分级：P0 体验严重受损 / P1 明显毛糙 / P2 可优化 / P3 风格选择差异

## 一、共性审查

### 1.1 色彩体系（整体一致性 >85%）

**高度一致的方面**：
- 主背景色 `(0.03, 0.05, 0.12)` 深蓝——全部 9 Screen 统一
- 标题栏：`(0.06, 0.08, 0.16)` 底色 + `(0.2, 0.36, 0.55)` 蓝顶线——7/8 可套标题栏的 Screen 精确一致（MainMenu 除外）
- 标题文字色 `(0.75, 0.85, 0.95)` 浅蓝灰——全部 7 个带标题栏 Screen 一致
- 金钱绿 `(0.3, 1.0, 0.3)` / 警告黄 / 危险红——全局统一

**色彩偏离项**：

| 级别 | 项 | 偏离描述 |
|------|----|---------|
| P1 | 返回按钮色系不统一 | Achievement/Options/Credits 用标准蓝 `(0.08,0.12,0.25)`, RewardScreen 用亮蓝 `(0.2,0.25,0.45)`, GameSaveScreen 用灰色 `(0.25,0.25,0.35)` |
| P2 | MainMenu 标题色孤立 | 金色 `(0.95,0.85,0.25)` 为全项目唯一金色——不在任何色板中，与其他界面冷色系脱节 |
| P2 | 绿色/红色多版本 | 绿色系 6+ 变体（`0.12,0.45,0.18` 到 `0.15,0.6,0.15`），红色系 5+ 变体——无统一的语义色定义 |
| P3 | GamePlayScreen HUD 额外底线 | 标题栏比其余 Screen 多一条 `(0.12,0.24,0.4)` 底线——游戏内特意为之 |

### 1.2 间距规范（多处偏离）

**一致的部分**：
- 标题栏高度 34px——8/8 Screen 完全一致
- 标准行高 44px——Achievement/Options 统一

**偏离项**：

| 级别 | 项 | 偏离描述 |
|------|----|---------|
| P1 | 返回按钮位置不统一 | Achievement/Credits/Options/Reward 放右上角（`backX=sw-116`），LevelSelect/GameSave 放左下角（`20, 20` 或 `36, bottom`）——用户需在不同 Screen 中"找"返回按钮 |
| P2 | 返回按钮尺寸 3 种 | `100x34`（Achievement/Options/Credits）、`110x36`（LevelSelect）、`140x45`（GameSave）——无统一规范 |
| P2 | MainMenu 无标题栏 | 9 Screen 中唯一没有标题栏的界面——视觉上断代 |
| P3 | 列表行高不一致 | 44px（Achievement）、52px（Reward）、60px（GameSave）——各有理由，但无统一的行高定义 |

### 1.3 字体尺寸层级（弱层级）

当前 9 Screen 的 `drawText` 调用无独立字号参数——所有文字使用同一渲染尺寸。视觉层级仅通过 RGB 颜色和位置暗示：
- 标题级：浅蓝灰 `(0.75,0.85,0.95)`
- 正文级：白/浅灰 `(0.78,0.82,0.88)` 到 `(1.0,1.0,1.0)`
- 辅助级：灰色 `(0.45,0.5,0.6)` 或 `(0.6,0.6,0.6)`

字符宽度估算也存在差异——MainMenu/LevelSelect 用 6px/字，Achievement/Credits 用 7px/字，导致居中偏移，差异约 16.7%。

**级别：P2**。功能无损但文本对齐细节粗糙。

### 1.4 UI 模式遵循率

| 模式 | 遵循率 | 说明 |
|------|--------|------|
| 标准标题栏 | 87.5% | 7/8，MainMenu 例外 |
| 标准面板（深色+蓝顶线+半透明） | 50% | 4/8 使用，其余自绘 |
| 返回按钮 | 75% | 6/8（MainMenu/GamePlayScreen 不需要），但位置/颜色/尺寸各异 |
| 按钮边缘高光线 | 70% | 7/10 使用，Reward/GameSave/Credits 按钮无边缘线 |

## 三、交互模式差距

### 3.1 触摸拖拽 → 桌面替代

| 原版 | 桌面版 | 评估 | 级别 |
|------|--------|------|------|
| 拖拽塔按钮放置 | 点击塔按钮 + 点击地图格 | 两步 vs 一步——操作路径更长但精确度更高 | P3 |
| 拖拽出按钮区取消 | 无对应 | 桌面版无防误触取消——再次点击塔按钮可取消选择，但不够直观 | P2 |
| 双指 Pinch 缩放 | 滚轮 + 滑块 | 滚轮无刻度反馈——滑块已补，等价 | P3 |

### 3.2 系统组件 → drawRect 模拟

| 组件 | 桌面替代 | 缺陷 | 级别 |
|------|---------|------|------|
| CheckBox | 绿色/灰色文字+方形开关 | 无勾选动画、无原生触控反馈 | P3 |
| TableLayout | 空格分隔文字 | RewardScreen 四列不对齐——视觉粗糙 | P1 |
| EditText（数字输入） | +/- 按钮 + 滑条 | 无法直接输入目标值——混合器需多击 | P3 |
| Button（原生状态管理） | drawRect 手动状态切换 | 无原生 hover/pressed/disabled 状态——代码手动维护 | P2 |

### 3.3 动画 → 简化

| 原版动画 | 桌面现状 | 影响 | 级别 |
|----------|---------|------|------|
| HudEntry 数字滚动（大步长跳转） | 直接赋值 displayMoney = target | 大量加分时玩家无法感知数值变化动量 | P1 |
| ScoreOverlay 9 状态（含倒计数） | 5 行淡入 | 功能完整，但无合计倒计数动画——视觉期待略欠 | P2 |
| TowerButton 8 帧滑入/滑出 | 无动画 | 塔按钮不是列表或弹窗——动画非必需 | P3 |
| UpgradeDialog 8 帧展开 + 自动暂停 | 无动画 + 需 ESC 手动暂停 | 对话框出现突兀——建议至少加 togglePause | P1 |

### 3.4 ESC 键状态机

原版 Back 键的三级状态机（取消升级 → 清除塔选择 → 退出确认）未在桌面版恢复。当前 ESC 直接清 activeTower + 打开暂停面板。

**级别：P2**。功能等价（清选择后再按 ESC 进入菜单），但缺少"取消升级对话框"的中间步骤——对话已打开时按 ESC 应只关闭对话而非直接进暂停。

### 3.5 对话框/弹窗

| 项 | 评估 | 级别 |
|----|------|------|
| 升级对话框无遮罩 | 点击面板外关闭无遮罩引导——误操作风险 | P1 |
| 确认对话框仅 MainMenu 有 | Achievement/Reward/GameSave 等界面无同类确认 | P2 |
| 弹窗无动画 | 面板即时出现——视觉突变 | P2 |

### 3.6 原版特有界面功能对标

| 原版 | 桌面现状 | 级别 |
|------|---------|------|
| ConcurrentBackground 动态换图 | 静态精灵图 + 暗色遮罩——P3 有意替代 | P3 |
| Android Options Menu (4 项) | ESC 暂停面板——等价 | P3 |
| LevelSelect EditText 键盘输入 | +/- 按钮——P3 桌面简化 | P3 |
| Achievement 已解锁/未解锁图标 | 文字 `OK` / `--`——P3 | P3 |
| Gameplay 内 BatteryLevel 图标 | `🔋 X%` 文本——已在计划③实现 | 通过 |
| 音效开关（LevelSelect 内） | 已在计划③实现（`prefs.putBool("enable_sound", !cur)`） | 通过 |

## 四、分级结论（汇总）

### P0 — 体验严重受损（2 项）

| # | 项 | 位置 | 影响 |
|---|----|------|------|
| P0-1 | 混合器面板数字箭头 **18x12px** | `LevelSelectScreen.java:372-376` | 远低于 24px 最小点击目标——反复点击箭头是主要交互路径 |
| P0-2 | 升级对话框无遮罩 + 无自动暂停 | `UiRenderer.java:renderUpgradeDialog` | 点击外部任何区域触发误操作，玩家注意力在弹窗上但游戏仍在运行 |

### P1 — 明显毛糙（10 项）

| # | 项 | 位置 |
|---|----|------|
| 1 | 返回按钮位置不统一（右上 vs 左下） | Achievement/Credits/Options/Reward vs LevelSelect/GameSave |
| 2 | 键盘快捷键无视觉提示（仅 15px 底部条） | `GamePlayScreen.java:539` / `LevelSelectScreen.java` |
| 3 | HudEntry 数字滚动动画缺失——直接跳转 | `GamePlayScreen.java:462-492`（displayMoney=target） |
| 4 | 升级对话框打开时不暂停游戏 | `UiRenderer.java:renderUpgradeDialog` |
| 5 | RewardScreen 表头用空格分隔而非列对齐 | `RewardScreen.java` |
| 6 | AchievementScreen 分类标签间距仅 5px | `AchievementScreen.java` |
| 7 | 继续游戏/存档加载按钮无 disabled 态 | `MainMenuScreen.java` / `GameSaveScreen.java` |
| 8 | AchievementScreen 滚动条 8px 宽 | `AchievementScreen.java` |
| 9 | 返回按钮色系不统一 | Reward `(0.2,0.25,0.45)` / GameSave `(0.25,0.25,0.35)` vs 标准蓝 |
| 10 | LevelSelect 键盘快捷键无视觉提示 | `LevelSelectScreen.java` |

### P2 — 可优化（12 项）

- HUD 信息拥挤（FPS/缩放/电量可弱化或可选）
- MainMenu 无标题栏
- 返回按钮尺寸无统一规范
- 字符宽度估算差 16.7%
- 绿色/红色无统一品牌色
- 按钮无原生 hover/pressed/disabled 状态管理
- 确认对话框仅 MainMenu 有
- Scroll 列表无 hover 高亮
- 控制按钮用 Unicode 文字非图标
- GameSave 新建存档行无视觉区分
- Credits 无手动滚动
- Credits 硬编码内容

### P3 — 风格选择差异（8 项）

- 科幻主题暗黑 vs Android 原生亮色
- 塔拖拽 → 点击放置（桌面适配）
- 双指缩放 → 滚轮
- 原生组件 → drawRect 模拟（全局架构）
- 动画简化（TowerButton 滑入/ScoreOverlay 倒计数/AchievementAlert 边框描绘）
- 暂停双实现（renderPauseMenu + overlay）
- ConcurrentBackground → 静态背景
- EditText → +/- 按钮

## 五、设计建议

### 5.1 立即修复（P0，2 项）

1. **混合器箭头加大到 24x16px 以上**：`LevelSelectScreen.java:372-376` 的 `drawRect(18, 12)` → 扩大到至少 `24x16`
2. **升级对话框加遮罩层 + togglePause**：`UiRenderer.renderUpgradeDialog()` 调用前绘制全屏半透明遮罩 `(0,0,sw,sh, 0,0,0,0.3)`，并暂停游戏

### 5.2 短期统一（P1，5 项）

3. **提取标题栏组件**：避免 7 Screen 重复，统一高度 34px + 色值常量
4. **统一返回按钮位置/大小/颜色**：全部放左上或左下，尺寸>=100x34，标准蓝色
5. **键盘快捷键面板**：每个需要键盘操作的 Screen 底部显示统一快捷键条（复用 GameSaveScreen 的底部条模式）
6. **HudEntry 恢复滚动动画**：step = Math.max(1, Math.abs(target - display) / 10) 的渐进逼近
7. **升级对话框加 togglePause**：`UiRenderer.showUpgradeDialog()` 时调用 `gameState.togglePause()`

### 5.3 后续优化（P2）

8. **品牌色定义**：在 `UiRenderer` 或新建 `UIColors` 类中集中定义绿色/红色/蓝色/黄色的语义版本
9. **统一行高标准**：菜单列表 44px、内容列表 52px、存档列表 60px 作为三种标准
10. **列表 hover 态**：鼠标悬停行时改变背景色
11. **确认对话框统一组件**：MainMenu 的确认框模式提取为可复用方法

### 5.4 供报告二（架构层）铺垫

- 标题栏组件提取 → 减少 7 Screen 中的重复 drawRect 代码
- drawRect 按钮统一包装 → `drawStandardButton(label, x, y, w, h, style)` 方法
- 列表/滚动统一 → `ScrollableList` 组件（复用 Achievement/Reward/GameSave 的共同需求）
