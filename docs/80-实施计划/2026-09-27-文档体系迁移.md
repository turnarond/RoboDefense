# 文档体系迁移实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 `docs/00-文档总纲.md` 把 `docs/` 迁移到分段编号形态，消除跨文档内容重复，并建立版本边界文档。

**Architecture:** 先纯 `git mv` 建立目标骨架（零内容 diff），再逐文档按唯一归属矩阵改写内容，最后按总纲 §11 清单做整体验收。校验器不在本计划范围（属配套工具集子项），本计划用可机械执行的 grep/计数断言替代。

**Tech Stack:** Markdown、git、Git Bash（Windows）。

**Spec:** `docs/00-文档总纲.md`（执行时与本计划一并阅读）

## Global Constraints

- 所有文档正文、注释、标题使用简体中文；专有名词（libGDX、LWJGL3、SQLite、GAP）保留英文。
- 文件与目录名使用中文并带两位数字前缀；`50-对外文章/` 与 `80-实施计划/` 内文件允许日期前缀。
- 活文档禁止 `文件名.java:行号` 形式定位代码，一律用符号名；`30-评审/`、`40-对照分析/` 快照取证例外。
- `VERSION` 是版本号唯一真源，当前值为 `2.6.0`；本计划设定的目标版本为 `2.7.0`。
- **提交授权**：用户已对本计划显式授权「仅本地 commit，不 push，限文档迁移范围」。每个任务结束时由
  实施者用本计划给出的提交信息原文本地提交；**任何情况下不得 `git push`**，不得改 `master`，
  不得提交 `.superpowers/` 等已忽略目录。
- 每步断言先执行看失败（红），做完改动再执行看通过（绿）。
