```
│              └───── SDBackup (SD卡) ────────┘       │
└─────────────────────────────────────────────────────┘
```

应用采用**双进程架构**：
- **菜单进程** (`com.magicwach.rdefense.menus`)：所有非游戏界面，内存占用低
- **游戏进程** (`com.magicwach.rdefense.game`)：仅 `GameActivity`，承载游戏引擎全部内存
- **进程间通信**：通过 `SharedPreferences` 和文件系统传递数据，无直接内存共享

## 2. 游戏主循环

### 2.1 线程模型

```
┌──────────────┐      postInvalidate()      ┌──────────────┐
│ Monitor线程   │ ─────────────────────────→ │ UI线程        │
│ (后台循环)    │       每~33ms              │ (Android主线程)│
│              │                            │              │
│ while(true)  │                            │ onDraw()     │
│   sleep(33)  │                            │   acquire()  │
│   postInv.() │                            │   nextState()│
│ end          │                            │   draw()     │
└──────────────┘                            │   playLoop() │
                                            └──────────────┘
```

- **Monitor 线程**：后台线程，每 ~33ms 调用 `postInvalidate()` 触发重绘
- **UI 线程**：在 `onDraw()` 中同步执行游戏逻辑更新和渲染
- **同步机制**：`Semaphore(state_request_sync)` 防止帧堆叠

### 2.2 帧更新流程

```
onDraw(Canvas)
  │
  ├─ state_request_sync.tryAcquire()   ← 是否有新帧请求
  │
  ├─ for i in 0..frame_skip:           ← 跳帧补偿（1~2帧）
  │   └─ GameState.nextState()
  │       ├─ 1. 回收已完成的 GameEvent
  │       ├─ 2. 出队成就通知
  │       ├─ 3. if 运行中:
  │       │   ├─ advanceActiveEnemiesState()  ← 移动所有敌人
  │       │   ├─ advanceTowersState()         ← 所有塔瞄准/射击
  │       │   ├─ advanceBulletsState()        ← 所有弹药移动/碰撞
  │       │   └─ advanceLevelState()          ← 生成新波次敌人
  │       └─ 4. grid_order.ensureSorted()     ← 维护渲染排序
  │
  ├─ Display.draw(Canvas, GameState)    ← 渲染全部画面
  │
  └─ SoundManager.playLoop()           ← 播放音效队列
```

| 层次 | 内容 | 说明 |
|------|------|------|

## 3. 核心子系统设计

### 3.1 网格与寻路系统

#### 数据结构

```
MovementGrid (每条路径一个实例)
┌───┬───┬───┬───┬───┬───┐
│ 0 │ → │ → │ → │ ↓ │ 6 │    0 = 可通行
├───┼───┼───┼───┼───┼───┤    1 = 右  2 = 上
│ 6 │ 6 │ 6 │ 6 │ ↓ │ 6 │    3 = 左  4 = 下
├───┼───┼───┼───┼───┼───┤    5 = 已放塔
│ 0 │ 0 │ 0 │ 0 │ ↓ │ 6 │    6 = 墙壁
├───┼───┼───┼───┼───┼───┤    7 = 终点
│ 0 │ 0 │ 0 │ 0 │ 7 │ 6 │    8 = 障碍物
└───┴───┴───┴───┴───┴───┘
```

- **寻路算法**：BFS 从终点向起点扩散，为每个可通行格子标记移动方向
- **路径验证**：放塔前运行 BFS 验证起点仍可达终点
- **多路径支持**：每条路径（起点→终点）有独立的 `MovementGrid`

#### 空间分区（CollisionGrid）

```
CollisionGrid (塔目标检测用)
┌────────┬────────┬────────┐
│ cell   │ cell   │ cell   │   每个 cell 大小 = 3 × GRID_PIXEL_SIZE
│ [E,E]  │ [E]    │ []     │
├────────┼────────┼────────┤   每帧重建：
│ []     │ [E,E,E]│ [E]    │   1. 清空所有 cell
├────────┼────────┼────────┤   2. 将所有敌人按位置插入 cell
│ []     │ []     │ [E]    │   3. 塔查询周围 cell 寻找目标
└────────┴────────┴────────┘
```

#### 伤害计算

```
applyDamage(amount, shot_type):
  switch shot_type:
    case 4 (减速):    slow_counter = max_slow      // 冰冻效果
    case 6,14 (火焰): fire_counter += fire_damage   // 持续灼烧
    case 12 (穿甲):   health -= amount              // 无视护甲
    case 13 (凝固弹): fire_counter += partial_fire   // 部分灼烧
    default:          health -= max(0, amount - armor) // 常规伤害
```

### 3.3 防御塔系统

#### 攻击流程

```
GameTower.nextState():
  │
  ├─ shot_delay > 0 ?
  │   └─ shot_delay--; return     ← 冷却中
  │
  ├─ active_enemy 存活且在范围内?
  │   └─ 继续瞄准当前目标
  │
  ├─ chooseTarget(CollisionGrid)
  │   ├─ 查询周围 cell 的所有敌人
  │   ├─ 过滤：是否飞行、是否已着火、是否在范围内
  │   └─ 选择最近的有效目标
  │
  ├─ 有目标?
  │   ├─ 计算方向 → last_direction
  │   ├─ 创建 Bullet (从对象池)
  │   ├─ shot_delay = TowerData.shot_delay
  │   └─ 触发音效
  │
  └─ 特殊塔处理:
      ├─ 地雷: handleMine() → 链式爆炸
      ├─ 传送: handleTeleport() → 敌人回起点
      └─ 冲击波: handleShockwave() → AoE减速+灼烧
```

#### 升级树结构

```java
// TowerData 中每个塔类型定义 upgrade_type[] 数组
// 示例：重炮(type=3) 的升级选项
upgrade_type[0] = 12;  // → 防空炮
upgrade_type[1] = 10;  // → 火焰塔
upgrade_type[2] = 0;   // → 出售
```

### 3.4 弹道系统

#### 运动模型

```
Bullet.nextState():
  │
  ├─ 目标存活?
  │   └─ 更新 targetx/targety 为目标当前位置（追踪）
  │
  ├─ 计算方向向量 → VectorLookup.scaleVector()
  │
  ├─ 弧形弹道? (迫击炮/炮弹: type 9,10,13)
  │   ├─ z += z_velocity
  │   ├─ z_velocity -= gravity
  │   └─ z <= 0 时命中
  │
  ├─ 直线弹道:
  │   ├─ x += vx, y += vy
  │   └─ 距离 < threshold 时命中
  │
  └─ 命中:
      ├─ target.applyDamage(power, type)
      ├─ 溅射? → 遍历周围敌人
      ├─ 爆炸? → 创建 ExplosionEvent
      ├─ 烟尾? → 创建 ParticleEvent
      └─ 回收到 bullet_pool
```

### 3.5 关卡生成系统

#### 波次生成算法 (LevelDataGenerator)

```
generate(difficulty_level, survival_mode):
  │
  ├─ 计算100关的波次数据
  │
  └─ for level_num in 0..99:
      │
      ├─ features = random_byte  ← 控制敌人组合
      │   ├─ bit 0-1: 飞行/地面/混合
      │   ├─ bit 2-3: 分组数量 (1-4)
      │   └─ bit 4-7: 敌人类型偏好
      │
      ├─ health = base × (1 + difficulty/10) × (1 + level_num/20)
      │   └─ 指数增长确保后期关卡有挑战
      │
      ├─ 按 health / enemy_type_health 计算数量
      │
      └─ 输出: [type, count, delay] × groups
```

## 5. 性能优化设计

### 5.1 对象池

```
Enemy 对象池:
  enemy_pool[]     ← 可复用的 Enemy 实例
  enemy_list[]     ← 当前活跃的敌人
  enemy_graveyard[]← 正在播放死亡动画的敌人

  deploy: pool → list
  death:  list → graveyard → pool

Bullet 对象池:
  bullet_pool[]    ← 可复用的 Bullet 实例
  bullet_list[]    ← 当前飞行中的弹药

  fire:   pool → list
  hit:    list → pool
```

### 5.2 自适应性能监控 (PerformanceMonitor)

```
skip_level (0 ~ 40):
  0-10:  正常渲染
  10-20: 减少烟雾粒子数量
  20-30: 减少火焰效果数量
  30-40: 减少爆炸动画帧数

帧时间滚动平均 → skip_level 自动调整
```

### 5.3 渲染排序 (GridObjectOrder)

- 使用 Y 坐标排序的双向链表
- 每帧仅在需要时调用 `ensureSorted()`（插入排序）
- 避免每帧完整排序的开销

### 5.4 数学优化

- **VectorLookup**：16×16 预计算向量查找表，避免实时三角函数
- **FastRandom**：256个预生成随机数数组，周期性刷新

### 8.2 塔属性混合

```
TowerData.applyMixerAdjustments(seed):
  random = new Random(seed)
  │
  for each tower_type:
    ├─ shot_delay × random(0.5 ~ 2.0)
    ├─ power × random(0.5 ~ 2.0)
    ├─ attack_radius × random(0.7 ~ 1.5)
    └─ cost × random(0.5 ~ 2.0)
    │
    └─ 约束检查：
        ├─ shot_delay >= 最小值 (防止机关枪)

        └─ cost >= 最小值 (防止免费塔)
```

## 9. 奖励与成就生效链路

### 9.1 奖励升级效果映射

23 种奖励由 `RewardData` 集中配置，分两类生效方式：
**数值类**（TYPE_POWER / PERCENT_POWER / PERCENT_SPEED / PERCENT_EFFECT）经
`RewardData.applyReward(baseValue, type)` 换算；**解锁类**（TYPE_UNLOCK）由取值口判断
`rewardLevel(type) > 0` 后切换分支。

| 奖励（常量 = ID） | 中文效果 | 接入点 |
|-------------------|----------|--------|
| `BULLET_UPGRADE` = 0 | 弹药威力↑ | `TowerData.power()` 类型 1/2/3/12/13 |
| `EXPLOSIVES_UPGRADE` = 1 | 火箭/导弹/迫击炮/地雷威力↑ | `TowerData.power()` 类型 7/8/9/14/15/16/17/20/21 |
| `ROCKET_SPEED_UPGRADE` = 2 | 火箭装填↑ | `TowerData.shotDelay()` 类型 7/8/9 |
| `ANTIAIR_SPEED_UPGRADE` = 3 | 防空导弹装填↑ | `TowerData.shotDelay()` 类型 14/15 |
| `ARTILLERY_SPEED_UPGRADE` = 4 | 迫击炮/火炮装填↑ | `TowerData.shotDelay()` 类型 16/17 |
| `FLAME_DURATION_UPGRADE` = 5 | 火焰持续伤害↑ | `TowerData.power()` 类型 10/11/22 |
| `SLOW_DURATION_UPGRADE` = 6 | 缓速塔作用时间↑ | `TowerData.power()` 类型 4/5/6 |
| `HEALTH_UPGRADE` = 7 | 基础生命值↑ | `GameState` 初始化 `starting_health` |
| `STARTING_CASH_UPGRADE` = 8 | 初始金钱↑ | `GameState` 初始化 `startingCash` |
| `TELEPORT_TOWER` = 9 | 解锁传送塔 | `TowerData.upgradeType()` |
| `MINE_TOWER` = 10 | 解锁地雷塔 | `TowerData.upgradeType()` |
| `URANIUM_SHELLS` = 11 | 重型机枪 → 穿甲弹（无视护甲） | `TowerData.shotType()`、`upgradeType()` |
| `NAPALM_SHELLS` = 12 | 火炮 → 凝固汽油弹 | `TowerData.shotType()` 类型 17 |
| `AIR_SNIPER` = 13 | 重型防空射程×2 | `TowerData.attackRadiusSq()` 类型 13 |
| `CHEAP_FIREWORKS` = 14 | 防空导弹升级成本降低 | `TowerData.cost()` 类型 15 |
| `SLOW_BURN` = 15 | 火塔附加减速 | `TowerData.shotType()` 类型 11 |
| `FLEA_MARKET` = 16 | 出售价值×1.5 | `TowerData.sellValue()` |
| `SCRAMBLER` = 17 | 被传送敌人受伤 | `GameTower` 传送分支 |
| `CANNONBALL` = 18 | 迫击炮/火炮伤害↑ | **未接入，见 9.3** |
| `BONUS` = 19 | 杀敌奖励翻倍 | `GameState` 结算分支 |
| `AIR_BURST` = 20 | 地雷可攻击空中单位 | `GameTower` 地雷目标筛选 |
| `SHOCKWAVE` = 21 | 地雷链附加减速与灼烧 | `GameTower` 地雷链长度判定 |
| `FLARE_TOWER` = 22 | 解锁火炬塔 | `TowerData.upgradeType()` |

**设计要点**：奖励不直接改写塔实例属性，而是在 `TowerData` 的属性取值口做集中换算。
因此读档后无需重放奖励效果，属性天然一致；新增数值奖励只需扩展映射，不触碰 `GameTower`。

### 9.2 成就检测点分布

88 项成就统一由 `AchievementData.increaseLevel()` 触发，检测点集中在以下位置：

| 检测点 | 覆盖的成就类别 |
|--------|---------------|
| `GameState.setMoney()` | 金钱里程碑 |
| `GameState.enemyDefeated()` | 击杀数 / 得分里程碑 |
| `GameState.nextLevel()` | 完美通关 / 快进 / 生存模式 |
| `GameState.gameWonAchievements()`（由 `endGame()` 调用） | 难度 / 地图 / 特殊成就，内部再调 `bigSpenderAchievement()`、`pyroAchievement()` |
| `GameTower.handleMine()` | 地雷连锁 |

**设计要点**：成就检测与渲染解耦——逻辑层只入队，弹窗由 `GamePlayScreen` 轮询
`AchievementData.dequeueEarned()` → `showAchievement()` 呈现，因此逻辑帧率变化不影响成就触发时序。
